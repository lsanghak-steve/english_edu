## 6. msv2 검수 및 단계별 적용 계획

### 6.1 목표와 진행 원칙

- **목표:** `msv1`의 기존 기능을 기준으로 `msv2`의 누락 기능과 오류를 보완한다. 현재 `msv2`는 기능 동등성 검수를 통과하지 않은 상태다.
- **2026-10-17 사용자 결정:** 우선 기획서에 보관하고, 기능을 한 번에 모두 넣지 않고 **하나씩 적용**한다.
- 아래 순서는 제안 순서다. 각 항목은 구현 → 해당 항목 테스트 → 기존 학습 흐름 회귀 확인 → 결과 기록 후 다음 항목으로 넘어간다.
- **기획 등록 / 로컬 구현 / 격리 테스트 / 브라우저·실DB 검증 / 운영 반영**을 구분한다. 코드가 있다는 이유만으로 완료 처리하지 않는다.
- 현재 동작 기준은 **퀴즈 1·2단계 필수, 3·4단계 선택 심화**다. 앞선 아이디어 백로그의 '3단계 필수' 등은 확정된 변경으로 취급하지 않는다.
- 학습 기록·오답·출석 데이터를 보존한다. 공통 결함이 있는 경우 `msv1`의 문제를 그대로 복제하지 않는다.

### 6.2 검수 근거와 한계

- 코드 비교 대상: `next_app/app/msv1/page.js`, 해당 화면이 사용하는 공용 컴포넌트, `next_app/app/msv2/page.js`, `next_app/app/msv2/engine.js`.
- `msv2` 격리 검수: **26개 시나리오의 동작 확인 또는 문제 재현**. 문제 재현 성공도 포함된 숫자이며, 26개 기능이 정상이라는 뜻은 아니다.
- 자동 로그인 수정 회귀 검수: **8개 시나리오 통과**.
- 자동 로그인 수정 후 `/`, `/modern-login`, `/msv1`, `/msv2`의 로컬 HTTP 응답: **4개 모두 200**.
- 브라우저 클릭, 모바일 화면, 실제 마이크·스피커, 실제 DB 저장 후 재조회는 미검증이다. HTTP 200과 격리 테스트를 실제 사용자 흐름 검증으로 대신하지 않는다.

### 6.3 첫 적용 항목: 특정 학생으로 자동 로그인되는 문제

**현재 상태: 로컬 수정 및 격리 테스트 완료 / 실제 브라우저 검증·커밋·푸시·운영 반영 대기.**

- **원인:** 첫 화면은 `localStorage.english_edu_current_user`가 존재하면 `/msv1`으로 이동했고, `msv1`은 그 값을 로그인된 사용자로 그대로 복원했다. 이전 학생 정보가 장기간 남아 있으면 다시 같은 계정으로 입장하는 구조였다.
- **로컬 수정:** 새 탭 세션 키 `flipvoca_student_session_v1`을 추가했다. 예전 장기 저장 정보와 예전 세션 키만으로는 로그인 상태를 복원하지 않는다.
- **의도한 동작:** 명시적으로 로그인한 현재 탭에서는 새로고침 시 해당 계정을 유지한다. 활성 탭 세션이 없으면 첫 화면 또는 로그인 화면을 제공한다.
- **연동 범위:** 첫 화면, 기존 로그인 화면, `msv1`의 사용자 복원·프로필 저장·로그아웃, `msv2`의 로그인·프로필 저장·로그아웃.
- **기록 보존:** 로그아웃은 로그인 정보만 정리하고 학생의 학습·출석 기록은 유지한다.
